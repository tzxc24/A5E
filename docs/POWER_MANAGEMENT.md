# 电源管理（0.3.104）

`meow-power.service` 是独立于桌面的监测服务。它每2秒读取电量计、充电器和CPU/GPU/DDR温度，发布 `/run/meow-power/state.json`。桌面停止、原生游戏运行时服务仍继续工作。Qt只读快照，不再写充电寄存器或直接恢复CPU频率。

## 电量与充电

- 剩余容量读取BQ27220的0x10、满充容量读取0x12，设计容量0x3C标为电量计配置值，不能当作电池标签容量。
- 百分比保留电量计估算并显示容量未确认；异常、过期、不同启动的快照显示未知，不伪造10000mAh或健康正常。
- 充放电依据有符号电流和SGM41511状态共同判断；冲突显示未知。AXP USB online不是Type-C插入证据。
- 移除自动写2.4A和虚假的容量学习向导。旧Qt校准文件保留但不应用，不改电池OTP、充电电压、电流或硬件温控。
- 电量计Temperature温度来源未确认，不标作电芯表面温度，也不用它替代充电器NTC。

## 软件温控

默认值是本设备的保守软件策略，不是芯片额定参数：75℃提醒；80℃持续4秒请求最高1008000kHz；85℃持续4秒请求停止原生游戏、返回桌面；低于75℃连续30秒解除限制。CPU/GPU/DDR温度缺失不解除保护。

息屏的低功耗级别通过`/run/meow-os/screen-sleeping`通知服务，由同一个频率控制器限制到408000kHz。热限制与息屏统一仲裁，退出/唤醒不会越过热限制。原始上限按boot保存，服务重启不丢失；恢复不覆盖其他管理者设置的更低上限。

低电量仅提醒：有效负电流且电压<=3400mV持续10秒；不依据未经确认的SOC强制关机或引导深放电。

启动游戏要求快照与本次启动一致、年龄不超过6秒、温度可用、未处于冷却且当前低于85℃。冷却时拒绝反复启动。热退出可能中断未保存的进度，目的是在系统复位前尽量退回桌面，不能承诺保住全部游戏进度。

配置文件 `/etc/meow-os/power-management.json` 必须root所有且不可由其他用户写入。安装保留已有配置，升级会重启服务使新代码生效。服务停止不会在热态抬高频率，恢复由服务持续确认冷却后完成。

## 运维和回滚

查看：`systemctl status meow-power.service`、`journalctl -u meow-power.service`、`cat /run/meow-power/state.json`。传感器错误会写日志并在界面提示。低温下重启服务验证恢复；不要用实际加热验证保护阈值。

本次实机备份位置在部署记录中列出。若要回滚，先停止游戏；若仍热，保持频率限制，待服务确认低于恢复阈值30秒后再停止服务和恢复二进制/单元。旧版本会重新引入充电参数自动写入与不可靠容量显示，因此不应在未知电池规格下长期使用旧电池管理逻辑。

软件无法代替散热片、通风和合格的供电硬件。电池实际容量、允许充电电流、适配器规格仍需要实物确认；现有热相关复位并未仅凭软件重构得到根因证明。

依据：TI [BQ27220 Technical Reference Manual](https://www.ti.com/lit/pdf/sluubd4)、SGMICRO [SGM41511 datasheet](https://www.sg-micro.com/rect/assets/d5875e35-e037-4d49-9050-ad61cb59692c/SGM41511.pdf)。
